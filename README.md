# نرم‌افزار حسابداری فروشگاهی (MyShopAccounting)

نرم‌افزار حسابداری کامل و آفلاین برای فروشگاه‌های کوچک — فارسی، راست‌به‌چپ، با تاریخ شمسی،
حسابداری دوطرفه واقعی، مدیریت انبار، فاکتور فروش و خرید، مدیریت چک با کد یکتا،
حساب‌های بانکی متعدد، گزارش‌های کامل، خروجی اکسل و پشتیبان‌گیری امن.

برنامه با **Electron + Node.js + SQLite** ساخته شده و برای **ویندوز ۱۰ و ۱۱** بسته‌بندی می‌شود.
هیچ بخشی از برنامه به اینترنت نیاز ندارد.

## نصب

۱. فایل `MyShopAccounting-Setup.exe` را اجرا کنید.
۲. مسیر نصب را تأیید کنید (پیش‌فرض: پوشه کاربر، بدون نیاز به دسترسی مدیر).
۳. پس از نصب، میان‌بر «حسابداری فروشگاه» در منوی استارت و روی دسکتاپ ساخته می‌شود.
۴. در اولین اجرا، صفحه راه‌اندازی باز می‌شود: نام فروشگاه، تلفن، نشانی، واحد پول،
   نرخ مالیات و موجودی نقدی فعلی صندوق را وارد کنید.

**نسخه قابل حمل:** فایل `MyShopAccounting-Portable.exe` بدون نصب اجرا می‌شود و
اطلاعات را در پوشه‌ای به نام `MyShopAccounting-Data` کنار خود فایل نگه می‌دارد
(مناسب برای اجرا از روی فلش).

## محل پایگاه داده و پشتیبان‌ها

پایگاه داده **هرگز داخل پوشه نصب برنامه ذخیره نمی‌شود** تا با به‌روزرسانی یا نصب مجدد پاک نشود.

| مورد | مسیر در ویندوز |
|---|---|
| پایگاه داده | `%APPDATA%\MyShopAccounting\data\shop.db` |
| پشتیبان‌ها | `%APPDATA%\MyShopAccounting\backups\` |
| گزارش خطاها | `%APPDATA%\MyShopAccounting\logs\app.log` |
| خروجی‌های اکسل و PDF | `%APPDATA%\MyShopAccounting\exports\` |

در نسخه قابل حمل، همه این پوشه‌ها داخل `MyShopAccounting-Data` کنار فایل اجرایی قرار می‌گیرند.

از داخل برنامه: **تنظیمات ← اطلاعات برنامه ← باز کردن پوشه داده‌ها**

### پشتیبان‌گیری

- **خودکار:** طبق فاصله تعیین‌شده در تنظیمات (پیش‌فرض روزی یک‌بار) و همچنین هنگام بستن برنامه.
- **دستی:** بخش «پشتیبان‌گیری» ← دکمه «ساخت نسخه پشتیبان جدید».
- پوشه مقصد پشتیبان‌ها قابل تغییر است (مثلاً روی درایو دیگر یا فلش).
- تعداد نسخه‌های نگهداری‌شده قابل تنظیم است؛ نسخه‌های قدیمی‌تر خودکار حذف می‌شوند.

پشتیبان با دستور `VACUUM INTO` ساخته می‌شود که یک کپی سالم و فشرده از پایگاه داده می‌سازد
و هرگز به فایل اصلی آسیب نمی‌زند.

## بازیابی اطلاعات

۱. وارد بخش **پشتیبان‌گیری** شوید.
۲. روی نسخه موردنظر دکمه **بررسی** را بزنید تا از سالم بودن آن مطمئن شوید
   (تعداد کالا، فاکتور، چک و سند نمایش داده می‌شود).
۳. دکمه **بازیابی** را بزنید و تأیید کنید.

> پیش از هر بازیابی، برنامه به‌طور خودکار یک **نسخه ایمنی** از وضعیت فعلی می‌گیرد
> (`backup_..._before-restore.db`). بنابراین بازیابی هیچ‌وقت اطلاعات فعلی را برای همیشه از بین نمی‌برد.

برای بازیابی از فایلی در مسیر دیگر (مثلاً فلش)، از دکمه **«بازیابی از فایل دیگر»** استفاده کنید.

## به‌روزرسانی برنامه

نسخه جدید `MyShopAccounting-Setup.exe` را روی نسخه قبلی نصب کنید.

- فایل‌های **برنامه** جایگزین می‌شوند.
- فایل‌های **اطلاعات شما** (`%APPDATA%\MyShopAccounting`) دست‌نخورده باقی می‌مانند.
- در اولین اجرای نسخه جدید، مهاجرت‌های لازم پایگاه داده به‌صورت خودکار و داخل تراکنش اجرا می‌شوند.

توصیه: پیش از به‌روزرسانی یک‌بار پشتیبان دستی بگیرید.

## ساخت نسخه نصبی از روی سورس

### روش ساده (ویندوز)

فایل `build-windows.bat` را روی یک کامپیوتر ویندوزی دابل‌کلیک کنید. این فایل:

۱. وجود Node.js را بررسی می‌کند
۲. وابستگی‌ها را نصب می‌کند
۳. موتور پایگاه داده را برای Electron آماده می‌کند
۴. آزمون‌های حسابداری را اجرا می‌کند
۵. نسخه نصبی و قابل حمل را می‌سازد

خروجی:

```
release\MyShopAccounting-Setup.exe
release\MyShopAccounting-Portable.exe
```

### روش دستی

پیش‌نیاز: **Node.js نسخه ۱۸ یا بالاتر** ([nodejs.org](https://nodejs.org))

```bash
npm install                 # نصب وابستگی‌ها (به‌طور خودکار ماژول بومی را برای Electron آماده می‌کند)
npm test                    # اجرای ۱۶۴ آزمون حسابداری
npm start                   # اجرای برنامه در حالت توسعه
npm run dist:win            # ساخت نسخه نصبی + قابل حمل ویندوز
```

دستورهای دیگر:

| دستور | کار |
|---|---|
| `npm run dist:setup` | فقط فایل نصبی |
| `npm run dist:portable` | فقط نسخه قابل حمل |
| `npm run pack` | بسته‌بندی بدون ساخت نصب‌کننده (برای تست) |
| `npm run test:ui` | آزمون خودکار رابط کاربری |
| `npm run icon` | ساخت مجدد آیکون برنامه |
| `npm run rebuild` | آماده‌سازی مجدد ماژول بومی برای Electron |

> **نکته:** ساده‌ترین و مطمئن‌ترین راه، ساخت روی خود ویندوز است.

### ساخت از روی لینوکس یا مک (اختیاری)

ساخت `.exe` روی لینوکس ممکن است ولی به دو نکته نیاز دارد:

۱. **Wine** برای ابزار `rcedit` (که ۳۲ بیتی است):

```bash
sudo dpkg --add-architecture i386 && sudo apt-get update
sudo apt-get install -y wine64 wine32:i386
```

۲. **ماژول بومی ویندوز**: `better-sqlite3` قابل کراس‌کامپایل نیست، پس باید نسخه
   از پیش ساخته‌شده ویندوز آن را دانلود کرد و اجازه نداد electron-builder دوباره
   آن را برای لینوکس بسازد:

```bash
# دریافت نسخه ویندوزی ماژول بومی
(cd node_modules/better-sqlite3 && npx prebuild-install -r electron -t 33.4.11 --platform win32 --arch x64)

# ساخت بدون بازسازی ماژول بومی
npx electron-builder --win nsis portable --x64 --publish never -c.npmRebuild=false
```

پس از ساخت، صحت خروجی را بررسی کنید — این فایل باید **PE32+ DLL ویندوزی** باشد، نه ELF لینوکسی:

```bash
file release/win-unpacked/resources/app.asar.unpacked/node_modules/better-sqlite3/build/Release/better_sqlite3.node
```

برای برگرداندن محیط توسعه لینوکسی پس از ساخت:

```bash
npm run rebuild
```

## درون‌ریزی کالا از PDF و اکسل

به‌جای ثبت دستی کالاها، می‌توانید فهرست کالا را از یک فایل وارد کنید:

**صفحه «کالاها» ← دکمه «📥 درون‌ریزی از PDF / اکسل»**

### فرمت‌های پشتیبانی‌شده

| فرمت | توضیح |
|---|---|
| `PDF` | لیست قیمت‌های چاپی؛ کد کالا، نام و ستون‌های قیمت به‌صورت خودکار تشخیص داده می‌شوند |
| `xlsx` / `xlsm` / `xls` | برگه‌های اکسل با سرستون فارسی یا انگلیسی |
| `csv` | فایل متنی با جداکننده کاما |

### روش کار

۱. فایل را انتخاب می‌کنید.
۲. برنامه فایل را می‌خواند و **پیش‌نمایش کامل** همه ردیف‌ها را نشان می‌دهد:
   وضعیت هر ردیف (جدید / به‌روزرسانی / تکراری)، نام، کد، قیمت خرید و فروش.
۳. ردیف‌های دلخواه را تیک می‌زنید و «ثبت کالاها» را می‌زنید.

**هیچ چیزی بدون تأیید شما در پایگاه داده نوشته نمی‌شود.** ثبت نهایی در یک تراکنش
انجام می‌شود؛ اگر ردیفی خطا بدهد، کل عملیات برگشت می‌خورد (مگر گزینه «رد کردن
ردیف‌های خطادار» فعال باشد).

### تشخیص خودکار در لیست قیمت PDF

- **طول کد کالا** از روی سازگاری نسبت قیمت‌ها تشخیص داده می‌شود (کد و قیمت در
  استخراج متن PDF به هم می‌چسبند؛ برنامه مرز درست را پیدا می‌کند).
- **نرخ مالیات بر ارزش افزوده** و **درصد سود** از سرصفحه لیست قیمت خوانده می‌شوند.
- **قیمت فروش بدون مالیات ذخیره می‌شود.** لیست‌های قیمت معمولاً ستون دوم را با
  مالیات چاپ می‌کنند؛ برنامه مالیات را کم می‌کند تا هنگام صدور فاکتور دوباره
  مالیات روی مالیات حساب نشود.

### گزینه‌های پیش‌نمایش

| گزینه | کاربرد |
|---|---|
| واحد پول (تقسیم بر ۱۰) | تبدیل ریال به تومان |
| نرخ مالیات ستون فروش | کسر مالیات از ستون قیمت فروش |
| ساخت قیمت فروش از درصد سود | وقتی فایل فقط قیمت خرید دارد |
| دسته و واحد پیش‌فرض | برای ردیف‌هایی که این ستون‌ها را ندارند |
| به‌روزرسانی کالاهای موجود | تطبیق با کد کالا یا بارکد |

### کاتالوگ‌های همراه برنامه

چند لیست قیمت آماده همراه برنامه نصب می‌شوند (کاتالیست و کاتاباکس پرو، هرکدام با
دو تیر سود ۲۰٪ و ۱۲٪). در همان پنجره درون‌ریزی با یک کلیک پیش‌نمایش و ثبت می‌شوند
— بدون نیاز به فایل PDF.

> درون‌ریزی فقط **کالا تعریف می‌کند**؛ موجودی و سند حسابداری ایجاد نمی‌کند.
> برای ورود موجودی، فاکتور خرید یا انبارگردانی ثبت کنید.

### فایل نمونه اکسل

دکمه «دریافت فایل نمونه اکسل» یک فایل با سرستون‌های درست می‌سازد:

`نام کالا` · `کد کالا` · `بارکد` · `واحد` · `دسته` · `قیمت خرید` · `قیمت فروش` ·
`حداقل موجودی` · `توضیحات`

فقط ستون «نام کالا» الزامی است.

## امکانات برنامه

### داشبورد
فروش، خرید و سود دوره؛ موجودی صندوق، کارتخوان‌ها و بانک‌ها؛ طلب از مشتریان و بدهی به تأمین‌کنندگان؛
ارزش انبار؛ چک‌های در جریان و سررسید گذشته؛ بدهکاران معوق؛ کالاهای رو به اتمام؛
نمودار روند ۱۴ روزه فروش/خرید/سود و نمودار ترکیب روش‌های دریافت.
فیلتر بازه: امروز، دیروز، این هفته، ماه جاری، ماه گذشته، امسال، بازه دلخواه.

### کالا و انبار
- نام، کد، بارکد، دسته، واحد، قیمت خرید و فروش، حداقل موجودی، توضیحات، فعال/غیرفعال
- **درون‌ریزی گروهی کالا از فایل PDF، اکسل و CSV** با پیش‌نمایش و تأیید ([توضیح کامل](#درونریزی-کالا-از-pdf-و-اکسل))
- جست‌وجو با نام/کد/بارکد، فیلتر، مرتب‌سازی، پشتیبانی از بارکدخوان
- کاردکس کامل کالا (ورود، خروج، اصلاح، انبارگردانی) با مانده لحظه‌ای
- انبارگردانی و اصلاح موجودی با سند حسابداری خودکار
- گزارش ارزش‌گذاری انبار و کالاهای رو به اتمام
- جلوگیری از موجودی منفی (قابل تنظیم)

### فاکتور فروش و خرید
- انتخاب سریع کالا با جست‌وجو یا اسکن بارکد
- تخفیف ردیفی و تخفیف کل فاکتور (سرشکن‌شده روی ردیف‌ها)
- مالیات بر ارزش افزوده با نرخ قابل تنظیم (پیش‌فرض ۱۰٪)
- **پرداخت ترکیبی**: نقدی + کارتخوان + بانکی + کارت به کارت + چک در یک فاکتور
- نسیه با ثبت خودکار مانده روی حساب طرف‌حساب
- ویرایش و حذف کامل فاکتور با برگشت دقیق انبار، حسابداری، پرداخت‌ها و چک‌ها
- چاپ حرفه‌ای A4 و فیش حرارتی ۸۰ میلی‌متری، پیش‌نمایش و خروجی PDF

### مدیریت چک ⭐
- **کد یکتای سیستمی** برای هر چک: `CHK-R-000001` (دریافتی) و `CHK-P-000001` (صادره)
- اتصال دائمی چک به فاکتور مربوطه
- ثبت شماره چک، شناسه صیادی، بانک، شعبه، نام دارنده/صادرکننده، تاریخ صدور و سررسید
- **جست‌وجو با**: کد یکتا، نام دارنده، شماره فاکتور، شماره چک، شناسه صیادی، نام طرف‌حساب یا مبلغ
- گردش وضعیت با سند حسابداری خودکار:
  - دریافتی: در جریان ← واگذار شده به بانک ← وصول شده / برگشتی / ابطال
  - صادره: در جریان ← پرداخت شده / برگشتی / ابطال
- تاریخچه کامل وضعیت‌ها با شماره سند حسابداری هر مرحله
- امکان **بازگردانی آخرین وضعیت** برای اصلاح اشتباه
- یادآوری چک‌های نزدیک سررسید هنگام اجرای برنامه + گزارش سررسید گذشته
- چاپ شناسنامه چک

### حساب‌های بانکی و کارتخوان ⭐
- تعریف **چند حساب بانکی و چند کارتخوان** به‌صورت همزمان
- برای هر حساب: عنوان، بانک، شعبه، **شماره حساب**، **شماره کارت** (۱۶ رقمی)،
  **شماره شبا** (IR + ۲۴ رقم)، نام صاحب حساب، مانده اولیه
- اعتبارسنجی و نرمال‌سازی خودکار شماره کارت و شبا
- مانده هر حساب مستقیماً از دفتر حسابداری محاسبه می‌شود (همیشه هماهنگ)
- گردش حساب هر بانک با مانده تجمعی و امکان چاپ
- تعیین حساب پیش‌فرض برای هر روش پرداخت

### طرف‌حساب‌ها
- مشتریان و تأمین‌کنندگان با مانده اولیه، تلفن، کد ملی، کد اقتصادی و نشانی
- پرونده کامل: جمع خرید/فروش، پرداخت‌ها، برگشتی‌ها، مانده و صورت‌حساب با مانده تجمعی
- چاپ و خروجی صورت‌حساب

### خزانه‌داری
- سند دریافت و پرداخت مستقل (با پرداخت ترکیبی و ثبت چک)
- اتصال سند به فاکتور یا ثبت علی‌الحساب
- هزینه با دسته‌بندی (اجاره، برق، آب، حقوق، حمل‌ونقل، ...) و دسته دلخواه
- درآمد متفرقه
- انتقال وجه بین صندوق/کارتخوان/بانک با کارمزد (بدون اثر بر سود)
- آورده و برداشت مالک

### برگشتی‌ها
- برگشت از فروش و برگشت از خرید متصل به فاکتور اصلی
- کنترل تعداد قابل برگشت هر ردیف
- برگشت دقیق موجودی، فروش، مالیات، بهای تمام‌شده و مانده طرف‌حساب
- امکان استرداد وجه همزمان

### گزارش‌ها
سود و زیان، خلاصه مالی روزانه، فروش، خرید، پرفروش‌ترین کالاها، مالیات بر ارزش افزوده،
مانده مشتریان، مانده تأمین‌کنندگان، چک‌ها، موجودی انبار، گردش خزانه، هزینه‌ها به تفکیک دسته.
همه گزارش‌ها با فیلتر تاریخ، خروجی اکسل و چاپ.

### دفاتر حسابداری
دفتر روزنامه، دفتر کل، تراز آزمایشی، ترازنامه، کدینگ حساب‌ها و **بررسی سلامت**
(تراز بودن اسناد، تطابق انبار با حساب ۱۰۶، سلامت فایل پایگاه داده).

### خروجی اکسل
یک فایل `.xlsx` با ۲۵ شیت فارسی و راست‌به‌چپ: فروش، خرید، برگشتی‌ها، کالاها، موجودی انبار،
گردش انبار، مشتریان، تأمین‌کنندگان، مانده‌ها، گردش صندوق/کارتخوان/بانک، حساب‌های بانکی،
چک‌ها، هزینه‌ها، درآمدها، دریافت و پرداخت، دفتر روزنامه، تراز آزمایشی، دفتر کل،
کدینگ حساب‌ها، سود و زیان و مالیات.

### روش قیمت‌گذاری موجودی

**میانگین موزون متحرک (Weighted Average Cost)**

برای هر کالا دو مقدار نگهداری می‌شود: تعداد موجودی و **ارزش صحیح موجودی**.
بهای هر واحد از تقسیم این دو به دست می‌آید. به این ترتیب مانده حساب ۱۰۶ همیشه
دقیقاً برابر جمع ارزش موجودی کالاهاست — این تطابق در بخش «بررسی سلامت» و در
آزمون‌های خودکار پس از هر عملیات بررسی می‌شود.

سود بر اساس **بهای واقعی تمام‌شده** محاسبه می‌شود، نه قیمت فروش.

### نمونه اسناد خودکار

فروش نقدی با مالیات:

```
بدهکار  صندوق                     ۱۳٬۲۰۰٬۰۰۰
    بستانکار  فروش                            ۱۲٬۰۰۰٬۰۰۰
    بستانکار  مالیات بر ارزش افزوده             ۱٬۲۰۰٬۰۰۰
بدهکار  بهای تمام‌شده کالای فروش‌رفته  ۸٬۰۰۰٬۰۰۰
    بستانکار  موجودی کالا                      ۸٬۰۰۰٬۰۰۰
```

فروش با پرداخت ترکیبی (نقد ۲ + کارتخوان ۵ + چک ۴ میلیون):

```
بدهکار  صندوق                       ۲٬۰۰۰٬۰۰۰
بدهکار  کارتخوان                    ۵٬۰۰۰٬۰۰۰
بدهکار  اسناد دریافتنی              ۴٬۰۰۰٬۰۰۰
    بستانکار  فروش                            ۱۰٬۰۰۰٬۰۰۰
    بستانکار  مالیات بر ارزش افزوده             ۱٬۰۰۰٬۰۰۰
+ سند بهای تمام‌شده
```

وصول چک:

```
بدهکار  بانک (حساب انتخابی)         ۴٬۰۰۰٬۰۰۰
    بستانکار  اسناد دریافتنی                    ۴٬۰۰۰٬۰۰۰
```

برگشت چک:

```
بدهکار  حساب مشتری                  ۴٬۰۰۰٬۰۰۰
    بستانکار  اسناد دریافتنی                    ۴٬۰۰۰٬۰۰۰
```

انتقال وجه (بدون اثر بر سود):

```
بدهکار  حساب مقصد
    بستانکار  حساب مبدأ
```

### ایمنی داده

تمام عملیات (فاکتور، برگشتی، پرداخت، چک، هزینه، انتقال، اصلاح انبار) داخل یک
**تراکنش پایگاه داده** انجام می‌شوند. اگر هر مرحله شکست بخورد، کل عملیات برگشت می‌خورد.
هیچ‌وقت حالتی مثل «فاکتور ثبت شد ولی سند حسابداری نخورد» رخ نمی‌دهد.

هر سند حسابداری پیش از ثبت اعتبارسنجی می‌شود: **جمع بدهکار باید دقیقاً برابر جمع بستانکار باشد**.
تمام مبالغ به‌صورت عدد صحیح ذخیره می‌شوند تا هیچ خطای اعشاری در حسابداری ایجاد نشود.

### امنیت

- `contextIsolation: true` و `nodeIntegration: false`
- رابط کاربری هیچ دسترسی مستقیمی به Node یا SQLite ندارد
- تنها یک پل امن با فهرست سفید کانال‌های مشخص در دسترس است
- پیمایش به آدرس‌های خارجی و باز شدن پنجره جدید مسدود است
- Content-Security-Policy روی صفحه اصلی فعال است

## آزمون‌ها

### آزمون حسابداری

```bash
npm test
```

۱۶۴ بررسی روی سناریوهای واقعی: فروش نقدی، کارتخوان، بانکی، نسیه، چکی و **ترکیبی**؛
خرید نقدی و نسیه؛ برگشت از فروش و خرید؛ هزینه؛ درآمد؛ انتقال وجه؛ دریافت از مشتری؛
پرداخت به تأمین‌کننده؛ ثبت، وصول و برگشت چک؛ اصلاح انبار؛ مالیات؛ بهای تمام‌شده؛
سود و زیان؛ خروجی اکسل؛ پشتیبان‌گیری و بازیابی.

پس از **هر** عملیات دو چیز بررسی می‌شود:

1. جمع بدهکار = جمع بستانکار در کل دفتر
2. مانده حساب ۱۰۶ = جمع ارزش واقعی موجودی انبار

سناریوی مرجع نیز اجرا می‌شود: صندوق ۱۰۰٬۰۰۰٬۰۰۰ → خرید ۱۰ عدد × ۲٬۰۰۰٬۰۰۰ →
فروش ۴ عدد × ۳٬۰۰۰٬۰۰۰ با مالیات ۱۰٪ → هزینه اجاره ۵٬۰۰۰٬۰۰۰، و همه اعداد
(موجودی، صندوق، فروش، مالیات، بهای تمام‌شده، سود ناخالص، هزینه، سود خالص) بررسی می‌شوند.

### آزمون رابط کاربری

```bash
npm run test:ui
```

برنامه واقعی را اجرا می‌کند، راه‌اندازی اولیه را انجام می‌دهد، اسناد واقعی ثبت می‌کند،
همه صفحه‌ها و همه گزارش‌ها را باز می‌کند و هر خطای کنسول را گزارش می‌دهد.
همچنین جست‌وجوی چک، تغییر وضعیت چک، پنجره درون‌ریزی کالا، پشتیبان‌گیری، ساخت PDF و
خروجی اکسل را بررسی می‌کند.

### آزمون درون‌ریزی کالا

```bash
PDF_DIR=<پوشه فایل‌های PDF> npm run test:import
```

۶۲ بررسی روی مسیر واقعی برنامه: خواندن لیست قیمت PDF و تطبیق ریاضی همه ردیف‌ها
(`قیمت فروش = قیمت خرید × (۱ + درصد سود)`)، ثبت کالاها، درون‌ریزی مجدد بدون ایجاد
تکراری، تبدیل ریال به تومان، درون‌ریزی از اکسل و CSV، کاتالوگ‌های همراه برنامه، و
بررسی اینکه درون‌ریزی هیچ اثری روی موجودی و دفاتر حسابداری نمی‌گذارد.
