# راه‌اندازی مدل لاما روی یک سرور جداگانه

اگر مدل را روی همان سروری که وردپرس است اجرا کنید، آدرس پیش‌فرض `http://127.0.0.1:11434/v1`
کار می‌کند و کار تمام است. این راهنما برای حالت دوم است: **مدل روی سرور جداگانه.**

در این حالت یک نکته حیاتی وجود دارد که اگر رعایت نشود، مدل شما روی اینترنت باز می‌ماند و
هر کسی می‌تواند از GPU شما استفاده کند: **اولاما به‌صورت پیش‌فرض هیچ احراز هویتی ندارد.**

---

## گام ۱ — نصب اولاما روی سرور مدل

روی سرور مدل (نه سرور وردپرس):

```bash
curl -fsSL https://ollama.com/install.sh | sh
ollama pull llama3.1:8b
```

### مدل را روی شبکه گوش‌به‌زنگ کنید

اولاما پیش‌فرض فقط به `127.0.0.1` گوش می‌دهد، یعنی از بیرون سرور اصلاً در دسترس نیست.
باید این را تغییر دهید:

```bash
sudo systemctl edit ollama
```

در ویرایشگری که باز می‌شود این را اضافه کنید:

```ini
[Service]
Environment="OLLAMA_HOST=0.0.0.0:11434"
```

سپس:

```bash
sudo systemctl daemon-reload
sudo systemctl restart ollama
```

بررسی کنید که بالا آمده:

```bash
curl http://localhost:11434/v1/models
```

## گام ۲ — امنیت (این گام را رد نکنید)

الان اولاما روی همه رابط‌های شبکه گوش می‌دهد و **هیچ رمزی ندارد**. سه راه، از ساده به بهتر:

### راه ۱ (ساده و امن) — فقط IP سرور وردپرس اجازه داشته باشد

روی سرور مدل، با فایروال فقط به سرور وردپرس اجازه بدهید:

```bash
sudo ufw allow from IP_سرور_وردپرس to any port 11434 proto tcp
sudo ufw deny 11434
sudo ufw enable
```

آدرسی که در افزونه می‌گذارید: `http://IP_سرور_مدل:11434/v1`
فیلد «کلید سرویس مدل» را خالی بگذارید.

> اگر هر دو سرور در یک شبکه خصوصی هستند (مثل شبکه داخلی یک دیتاسنتر)، از IP خصوصی
> استفاده کنید و پورت را اصلاً روی اینترنت باز نکنید. این امن‌ترین حالت است.

### راه ۲ (پیشنهادی) — Nginx جلوی اولاما با HTTPS و کلید

یک لایه Nginx بگذارید که هم TLS داشته باشد و هم کلید بخواهد. روی سرور مدل:

```nginx
server {
    listen 443 ssl;
    server_name llm.example.com;

    ssl_certificate     /etc/letsencrypt/live/llm.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/llm.example.com/privkey.pem;

    location /v1/ {
        # افزونه کلید را به شکل Bearer می‌فرستد. هر چیزی جز کلید درست، رد می‌شود.
        if ($http_authorization != "Bearer YOUR_LONG_RANDOM_KEY") {
            return 401;
        }

        proxy_pass http://127.0.0.1:11434/v1/;
        proxy_set_header Host $host;

        # مدل روی CPU کند است؛ مهلت پیش‌فرض ۶۰ ثانیه Nginx وسط کار قطع می‌کند.
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
}
```

کلید را با این دستور بسازید (یک‌بار، و جایی امن نگه دارید):

```bash
openssl rand -hex 32
```

بعد اولاما را برگردانید به حالت محلی تا فقط از طریق Nginx در دسترس باشد:
مقدار `OLLAMA_HOST` را به `127.0.0.1:11434` برگردانید و Nginx را ری‌استارت کنید.

آدرسی که در افزونه می‌گذارید: `https://llm.example.com/v1`
کلید سرویس مدل: همان `YOUR_LONG_RANDOM_KEY`.

### راه ۳ — تونل SSH

اگر نمی‌خواهید هیچ پورتی باز کنید، روی سرور وردپرس:

```bash
ssh -N -L 11434:localhost:11434 user@IP_سرور_مدل
```

آن‌وقت آدرس در افزونه همان `http://127.0.0.1:11434/v1` می‌ماند. برای اینکه تونل دائمی
باشد از `autossh` یا یک سرویس systemd استفاده کنید.

## گام ۳ — تنظیم در افزونه

**باهوش ← تنظیمات ← مغز تحلیلگر**

| فیلد | مقدار |
|---|---|
| مدل زبانی | لاما روی همین سرور |
| آدرس سرویس مدل | آدرس سرور مدل، طبق راه انتخابی بالا |
| نام مدل | `llama3.1:8b` (یا هر چه `ollama list` نشان می‌دهد) |
| کلید سرویس مدل | فقط در راه ۲ پر می‌شود |

ذخیره کنید، بعد روی **«تست اتصال مدل»** بزنید. اگر فهرست مدل‌ها آمد، اتصال برقرار است.

> اسم گزینه «لاما روی همین سرور» است ولی با سرور راه دور هم دقیقاً همان‌طور کار می‌کند —
> تنها تفاوت آدرسی است که وارد می‌کنید. اگر آدرس خالی بماند، پیش‌فرض محلی استفاده می‌شود.

### هر سه شکل آدرس پذیرفته است

افزونه خودش مسیر را کامل می‌کند، پس هر کدام از این‌ها درست است:

```
https://llm.example.com
https://llm.example.com/v1
https://llm.example.com/v1/chat/completions
```

## گام ۴ — تست واقعی

از **سرور وردپرس** (نه از لپ‌تاپ خودتان) این را اجرا کنید:

```bash
curl -s https://llm.example.com/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_LONG_RANDOM_KEY" \
  -d '{"model":"llama3.1:8b","messages":[{"role":"user","content":"سلام"}]}'
```

اگر اینجا جواب گرفتید ولی افزونه نگرفت، مشکل از PHP است نه از شبکه: بعضی هاست‌ها
`wp_remote_post` را به دامنه‌های بیرونی محدود می‌کنند. ثابت `WP_HTTP_BLOCK_EXTERNAL` را
در `wp-config.php` بررسی کنید؛ اگر روشن است، دامنه مدل را به `WP_ACCESSIBLE_HOSTS` اضافه کنید:

```php
define( 'WP_ACCESSIBLE_HOSTS', 'llm.example.com' );
```

## عیب‌یابی

| پیام در افزونه | معنی | راه‌حل |
|---|---|---|
| «اتصال برقرار نشد» | پورت بسته است یا سرویس بالا نیست | `systemctl status ollama` و قوانین فایروال |
| «سرویس مدل با کد ۴۰۱ پاسخ داد» | کلید اشتباه است | کلید Nginx و فیلد افزونه را مقایسه کنید |
| «مدل … را نمی‌شناسد» | مدل روی سرور دانلود نشده | `ollama pull llama3.1:8b` روی سرور مدل |
| «در زمان تعیین‌شده پاسخ نداد» | مدل کند است یا Nginx وسط کار قطع می‌کند | `proxy_read_timeout` را زیاد کنید، یا مدل کوچک‌تر بگیرید |
| ۵۰۲ از Nginx | اولاما پایین است | `sudo systemctl restart ollama` |

## چند نکته درباره سخت‌افزار

- بدون GPU، مدل `8b` روی CPU حدود ۳۰ تا ۹۰ ثانیه برای یک تحلیل وقت می‌گیرد. افزونه تا
  ۱۲۰ ثانیه صبر می‌کند.
- با GPU (حتی یک کارت ۸ گیگابایتی) همان مدل چند ثانیه‌ای جواب می‌دهد.
- اگر سرور ضعیف است، `llama3.2:3b` را امتحان کنید؛ تحلیلش ساده‌تر است ولی سریع.
- تحلیل فقط وقتی اجرا می‌شود که روی دکمه بزنید — پس مدل بین دو تحلیل بی‌کار است و
  می‌توانید همان سرور را برای کار دیگری هم استفاده کنید.

## اگر مدل قطع شد چه می‌شود

هیچ صفحه‌ای خالی نمی‌ماند. موتور قانون‌محور داخلی همان Factها را تحلیل می‌کند و بالای
نتیجه می‌نویسد که خروجی از مدل نیامده. فروشگاه و رهگیری اصلاً به مدل وابسته نیستند.
