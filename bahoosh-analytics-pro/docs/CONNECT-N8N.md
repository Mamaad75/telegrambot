# اتصال باهوش به n8n

با این روش، تحلیل را ورک‌فلو n8n انجام می‌دهد و کلید OpenAI هرگز وارد وردپرس نمی‌شود.

## آنچه افزونه می‌فرستد

افزونه یک `POST` با بدنه JSON به آدرس وبهوک شما می‌زند:

```json
{
  "source": "bahoosh-analytics-pro",
  "version": "4.5.0",
  "site_id": "local_ab12cd34",
  "run_id": "run_9f2c…",
  "system_prompt": "You are an e-commerce analyst…",
  "packet": {
    "facts": [
      { "id": "fact_affinity_10_11", "kind": "commerce.product_affinity",
        "label": "خرید مشترک «رژ لب مات» و «تینت لب»",
        "value": { "together": 12, "lift": 1.3 }, "sample_size": 12 }
    ],
    "data_quality": { "score": 62, "warnings": [] }
  }
}
```

`system_prompt` را خود افزونه می‌سازد، پس لازم نیست پرامپت را در n8n نگه دارید و
با هر به‌روزرسانی افزونه دستی هماهنگش کنید.

## آنچه باید برگردانید

فقط JSON، با این ساختار:

```json
{"recommendations":[{
  "title":"«رژ لب مات» و «تینت لب» را پکیج کنید",
  "summary":"این دو ۱۲ بار با هم خریده شده‌اند…",
  "rationale":"…",
  "priority":"high",
  "confidence":82,
  "impact":"افزایش میانگین سبد",
  "evidence":["fact_affinity_10_11"]
}]}
```

**قانون مهم:** هر پیشنهاد باید در `evidence` به شناسه یکی از Factهایی که فرستادیم اشاره
کند. پیشنهادی که به Fact ناموجود اشاره کند، پیش از نمایش حذف می‌شود — این همان چیزی است
که جلوی عدد‌سازی مدل را می‌گیرد. اگر هیچ پیشنهادی از این فیلتر رد نشود، افزونه پیام
«پاسخ وبهوک هیچ پیشنهاد معتبری نداشت» می‌دهد.

فیلد `action` ننویسید؛ نادیده گرفته می‌شود. تصمیم اینکه چه چیزی قابل اجراست با خود
افزونه است.

## تغییراتی که در ورک‌فلو فعلی شما لازم است

بر اساس اسکرین‌شاتی که فرستادید (Webhook → Analyze With OpenAI → Respond):

### ۱. گره Webhook

- **HTTP Method:** `POST` ✅ (همین است)
- **Respond:** روی `Using Respond to Webhook node` بگذارید.
- بعد از ذخیره، **ورک‌فلو را Active کنید** و آدرس **Production URL** را کپی کنید،
  نه Test URL. آدرس تست فقط تا یک اجرا زنده است و بعدش ۴۰۴ می‌دهد.

### ۲. گره Analyze With OpenAI

دو تغییر:

**الف) پیام‌ها را از ورودی بخوانید.** به‌جای پرامپت ثابت:

- System message:
  ```
  {{ $json.body.system_prompt }}
  ```
- User message:
  ```
  {{ JSON.stringify($json.body.packet) }}
  ```

> اگر گره Webhook شما بدنه را بدون `body` می‌دهد (بسته به نسخه n8n)، از
> `{{ $json.system_prompt }}` و `{{ JSON.stringify($json.packet) }}` استفاده کنید.
> یک‌بار ورک‌فلو را اجرا کنید و در خروجی Webhook ببینید داده زیر `body` هست یا نه.

**ب) خروجی JSON بخواهید.** در تنظیمات گره، `Output Content as JSON` یا
`Response Format: JSON` را روشن کنید تا مدل متن اضافه ننویسد.

### ۳. گره Respond

- **Respond With:** `Text` یا `JSON` — هر دو کار می‌کند.
- اگر `Text` گذاشتید، مقدارش: `{{ $json.message.content }}` یا `{{ $json.text }}`
  (بسته به اینکه گره OpenAI خروجی را با چه کلیدی می‌دهد).

افزونه چند شکل مختلف را می‌پذیرد (`output`، `text`، `content`، `message`، `response`،
`result`، `data` و آرایه تک‌آیتمی)، پس اگر دقیق نبود هم معمولاً خوانده می‌شود.

### ۴. گره Fetch Website

در اسکرین‌شات به جایی وصل نیست و لازم هم نیست — افزونه خودش داده را می‌فرستد و
مدل نباید سایت را بخواند. می‌توانید حذفش کنید.

## امنیت: این را جدی بگیرید

آدرس وبهوک n8n **عمومی و بدون رمز** است. هر کسی که آن را داشته باشد می‌تواند به آن
درخواست بزند و اعتبار OpenAI شما را خرج کند.

در افزونه، فیلد **«کلید سرویس مدل»** را با یک مقدار تصادفی پر کنید:

```bash
openssl rand -hex 32
```

افزونه آن را در دو هدر می‌فرستد: `Authorization: Bearer …` و `X-Bahoosh-Token: …`

در n8n، بعد از گره Webhook یک گره **IF** بگذارید:

- Condition: `{{ $json.headers['x-bahoosh-token'] }}` **equals** کلید شما
- شاخه false → گره **Respond to Webhook** با کد `401`

یا ساده‌تر: در تنظیمات گره Webhook، **Authentication → Header Auth** را فعال کنید و
همان نام هدر و مقدار را بگذارید.

## حریم خصوصی: چه چیزی از سایت خارج می‌شود

بسته ارسالی **هیچ مشتری‌ای ندارد** — نه نام، نه ایمیل، نه شماره، نه شناسه بازدیدکننده.
ولی **نام محصولات، تعداد سفارش و مبلغ فروش** دارد، و این‌ها از سایت شما خارج می‌شوند و
از n8n به OpenAI می‌روند.

این دقیقاً نقطه مقابل گزینه «سرور لاما»ست: آنجا هیچ داده‌ای از شبکه شما خارج نمی‌شود ولی
باید سرور و GPU تأمین کنید؛ اینجا زیرساخت نمی‌خواهید ولی ارقام فروشتان به یک سرویس
بیرونی می‌رود. انتخابش با شماست — فقط با آگاهی انتخاب کنید.

## تست

**باهوش ← تنظیمات ← مغز تحلیلگر**:

| فیلد | مقدار |
|---|---|
| مدل زبانی | وبهوک اتومیشن (n8n / Make / Zapier) |
| آدرس سرویس مدل | `https://kiyarashnd22.app.n8n.cloud/webhook/analyze-website` |
| کلید سرویس مدل | همان کلید تصادفی (اگر گام امنیت را انجام دادید) |
| نام مدل | خالی — برای وبهوک استفاده نمی‌شود |

ذخیره کنید و **«تست اتصال مدل»** را بزنید. این دکمه یک بسته کوچک واقعی با یک Fact
آزمایشی می‌فرستد و بررسی می‌کند که پاسخ قابل خواندن باشد — نه فقط اینکه سرور زنده است.

## اگر کار نکرد

| پیام | معنی | راه‌حل |
|---|---|---|
| «وبهوک پیدا نشد» (۴۰۴) | ورک‌فلو Active نیست یا آدرس Test را گذاشته‌اید | Active کنید و Production URL را کپی کنید |
| «با کد ۴۰۱ پاسخ داد» | کلید هدر با n8n نمی‌خواند | مقدار گره IF یا Header Auth را بررسی کنید |
| «هیچ پیشنهاد معتبری نداشت» | مدل JSON درست برنگرداند یا به Fact ناموجود اشاره کرد | خروجی JSON را روشن کنید و مطمئن شوید `evidence` از شناسه‌های ارسالی استفاده می‌کند |
| «با کد ۵۰۰ پاسخ داد» | گره داخل ورک‌فلو خطا داده | در n8n بخش Executions را ببینید |

اگر وبهوک جواب ندهد، صفحه خالی نمی‌ماند: موتور قانون‌محور داخلی همان اعداد را تحلیل
می‌کند و بالای نتیجه می‌نویسد که پاسخ از مدل نیامده.
